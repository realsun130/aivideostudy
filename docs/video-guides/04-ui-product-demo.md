# Guide Book 04：UI / 产品演示

用代码重建产品界面，配合光标、点击、放大镜头演示一个功能流程。比录屏干净、可改、能多语言出版本。

## 一、适用场景
- 新功能发布、落地页头图视频、应用商店预览、教程片段。
- 界面会改版、需要随时重出。
- 需要多种画幅（16:9、1:1、9:16）同一内容。

## 二、不适用
- 只是想快速给同事看一下：直接录屏更快。
- 流程非常长、操作很多：用实拍录屏 + 10 的包装方式。

## 三、实施流程
1. 写演示脚本：每一步“用户做了什么 → 界面变成什么”，每一步一句话。
2. 只重建需要出现的界面部分（截图做底图 + 代码重建会动的元素），不追求整个应用。
3. 定镜头：哪一步推近、推多少，哪一步回到全景。
4. 光标路径：起点、终点、点击帧；点击时界面反馈晚一点出现。
5. 用 `TransitionSeries` 把每一步做成一个场景（`multi-scene-video.md`）。
6. 出静帧检查每一步的状态，按帧号改。

## 四、技术要点
- 界面元素用 React 组件写，状态由帧号决定：`const step = frame < 60 ? 0 : 1`，不要用 `useState` 和定时器（ML §1）。
- 截图做底图用 `<Img>`（`remotion-markup/images.md`），渲染前确保加载完成。
- 镜头推近：在外层容器用 `scale` + `translate`，曲线比物体更软（ML §3：镜头用 ease-in-out-quart）。
- 点击音、切换音：`sfx.md` 里有 `mouse-click.wav`、`switch.wav`、`whoosh.wav`。
- 多画幅：同一组件注册多个 `<Composition>`，宽高不同（`compositions.md`）。
- 高亮注释：`text-highlights.md` 的 `<Box>` / `<Underline>`。

## 五、时间缓动与叙事
| 项 | 数字 | 来源 |
|---|---|---|
| 按下反馈 | < 150 ms | MDS `reference/timing-easing-tables.md` |
| 松开 / 落定 | 200–300 ms | 同上 |
| 卡片进出 | 200–350 ms | 同上 |
| 弹窗 | 300–400 ms | 同上 |
| 页面切换 | 400–600 ms | 同上 |
| 距离换算 | 100px=1.0×，200px=1.3×，400px=1.6×，全屏 1.8–2.0× | 同上 |
| 按钮按下配方 | 0.97（50 ms）→ [1.04,0.96]（100 ms）→ 1.02 → 1.0（弹簧 200 ms） | MDS `SKILL.md` Button Press |
| 光标移动 | ease-in-out，不走直线（**起始值**：轻微弧线） | MDS 弧线原则 |
| 每步停留 | 1.5–3 s（**起始值，需调**） | — |

注意：MDS 的时长是给真实交互用的。视频观众没有亲手操作，**演示里通常要比真实 UI 慢一些**，能看清因果。叙事上先让光标到位，再点击，再看结果（原因先于结果）。

## 六、验收清单
- [ ] 每一步的因果都看得清：点了哪里 → 什么变了。
- [ ] 推近时界面文字清晰（底图分辨率够，`scale` 不超过 1 倍放大底图）。
- [ ] 光标没有突然跳位。
- [ ] 每种画幅都没裁掉关键元素。
- [ ] 点击音晚画面 1 帧。
