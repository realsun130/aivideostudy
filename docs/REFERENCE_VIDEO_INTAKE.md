# 参考视频拆片（Reference Video Intake）

> 用户贴一段喜欢的视频 → 先拆、再说保留/改什么、报成本、出 10–15 s 样片，用户点头才开全片。动效相关先读 [`MOTION_LESSONS.md`](MOTION_LESSONS.md)。思路参考 OpenMontage 的 reference-first 流程，模板为本仓库自写。

## 0. 输入
- 链接或文件；用户一句话说“喜欢它什么”（必问，不猜）。
- 代码先跑：`ffprobe` 时长/fps/分辨率；场景切点（`ffmpeg -vf "select='gt(scene,0.3)',showinfo"`）；每镜 1 张中帧拼联系表；响度（ebur128）。数字全由代码出，模型只看证据。

## 1. 逐镜拆解：5 个维度（每镜每维都填，没有就写 **N/A**，不许跳过）
| 镜 | 时间 | ① 画面/风格（媒介、配色、线条、光） | ② 运动（镜头运动、主体动作、缓动/弹簧感） | ③ 节奏（停留秒数、切点是否卡拍、转场） | ④ 叙事作用（hook/setup/payoff…，对应 `information_role`） | ⑤ 声音（音乐、音效、配音、响度） |
|---|---|---|---|---|---|---|
| 01 | 0.0–2.1 s | | | | | |
| 02 | | | | | | N/A |

汇总：平均镜长、最短/最长镜、运动镜头占比（帧差）、字卡占比、钩子在第几秒。

## 2. 保留 / 改 清单
| 项 | 保留 / 改 / 不做 | 原因 | 落到哪个文件 |
|---|---|---|---|
| 例：三色油印 + 米色纸 | 保留 | 用户点名喜欢 | `style_bible.json`（走 Style Lock） |
| 例：每 0.8 s 一切 | 改为 1.5–2.5 s | 我们有对白字幕，需阅读时间 | `motion_profile.json` pacing |
| 例：实拍转场 | 不做 | 纯程序化路线 | — |

## 3. 成本预估（写进 `cost_log.json` 的 estimate）
| 阶段 | 估算 | 修订上限 |
|---|---|---|
| 拆片 + Style 映射 | token 量 / 美元 | 1 |
| 10–15 s 样片 | 渲染分钟 + token | 2 |
| 全片（按镜数 × 单镜成本） | | 每镜 2 |
实际超估算 30% 由 `tools/cost_check.py` 告警并转人工。

## 4. 样片门（10–15 s，必过）
- 选最有代表性的 2–4 镜，做 10–15 s 动态样片（不是静帧）。
- 过 `tools/final_review.py`（status=pass），附联系表。
- 用户明确“可以”才进入全片；否则只改 1–2 条意见后重出样片（ML §5）。
- 结果记 `decision_log`（`stage: style_lock`，`user_visible: true`）。
